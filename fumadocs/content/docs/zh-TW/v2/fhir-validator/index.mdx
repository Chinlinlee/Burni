Profile validation 打遠端 [Inferno FHIR validator wrapper](https://github.com/Chinlinlee/inferno-fhir-validator-wrapper)。Burni 不內嵌 Java validator，也不載入 IG。決策寫在 `docs/adr/0001-remote-fhir-validator.md`。

<Callout type="info" title="ENABLE_VALIDATOR 不是 $validate 的開關">
`$validate` 永遠存在。`ENABLE_VALIDATOR=false` 只做 mongoose 結構檢查。`true` 才會等遠端 Validator。
</Callout>

## 設定

`ENABLE_VALIDATOR=true` 時：

| 變數 | 必填 | 意義 |
| --- | --- | --- |
| `VALIDATOR_URL` | 是 | Inferno `POST /validate` 的絕對 `http`/`https` URL，例如 `http://localhost:4567/validate`。Burni 不會自己補 `/validate`。 |
| `VALIDATOR_TIMEOUT_MS` | 否 | 正整數毫秒。預設 `30000`。`0` 或非整數會讓啟動失敗。 |

啟動只檢查這些值，不會 ping Validator。關掉時兩個變數都忽略。

## 請求

Burni 把 resource JSON `POST` 到 `VALIDATOR_URL`。有 `meta.profile` 才加 `?profile=`（逗號分隔）。不讀 `$validate?profile=`，不拆 Parameters，不重試。

StructureDefinition 和 IG package 在 Inferno 服務載入（[REST API](https://github.com/Chinlinlee/inferno-fhir-validator-wrapper/blob/main/rest-api.md)），不要放進 `utils/validator/igs`。

## 哪些 API 會打 Validator？

開啟時：

- create、update：寫入前先等 Validator。驗證失敗 422。Validator 不可用 503 或 502。resource 不進庫。
- Bundle 裡的 create/update：同一套規則。
- `$validate`：OperationOutcome 沒有 error 或 fatal 回 200，有則 422。

關掉時，這些 API 仍做 mongoose 結構檢查（寫入還會驗 contained）。

## HTTP status

Inferno 通常 HTTP 200 帶回 OperationOutcome。Burni 再對應：

| 情況 | Status | Body |
| --- | --- | --- |
| OperationOutcome issue 嚴重度為 `error` 或 `fatal` | 422 | Validator 的 OperationOutcome |
| 只有 information 或 warning | 200 | Validator 的 OperationOutcome |
| 連不上或 timeout | 503 | Burni 組的 OperationOutcome |
| 有 HTTP 回應但 body 不是 OperationOutcome | 502 | Burni 組的 OperationOutcome |
